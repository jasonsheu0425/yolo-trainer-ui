# v0.11.1 Architecture Hardening Report

## Before

TrainPage directly combined widget values, CLI construction, runtime lookup,
and runner lifecycle. Simple Mode updated Train widgets to share behavior.
Training Analysis UI knew the analyzer entry point directly. Important JSON
writes used more than one local implementation.

## After

- `domain.training.TrainingConfig` is the shared train input boundary.
- `TrainingService` owns the one canonical config-to-command conversion,
  runtime lookup, and train runner coordination.
- Simple Mode supplies a typed config to TrainPage's public render method.
- `AnalysisService` isolates the Training Analysis page from cache/analyzer
  orchestration.
- `persistence.atomic_writer` handles settings and analysis cache writes;
  `TrainingAnalysisStore` owns analysis-cache filesystem mechanics.
- `NavigationController` expresses stable page IDs rather than stack indexes.
- `TaskState` documents common runner/worker state vocabulary.

## Remaining Debt

Predict, Validate, Export, Dataset Builder, and Runtime retain their stable
page-level orchestration to avoid a risky broad rewrite. MainWindow still owns
page registration and a small amount of explicit workflow routing. Existing
runner wrappers remain for semantic clarity.

## Next: v0.12 Annotation Editor

Add an `annotation` domain module, `AnnotationService`, and annotation UI as a
new feature slice. Future inference must be an asynchronous worker that owns
model residency; widgets must neither load models nor directly manipulate
runtime internals.
